# 工程师决策树

**REQUIRED SUB-SKILL:** `grilling`。

事实（表里有没有某技能、已有专家怎么挂载、材料里有哪些字段）自己查。只有工程师取舍才提问。推荐答案必须写出，但在用户回答前不得当已采纳。

宿主有 `ask_user_question` 时，把当轮 frontier 一次交给它并等待。否则按 grilling 格式输出后停止本轮。

平台 `ask_user_question` 只出现在交付的 Agent.md 里，给师生用。

## 第一轮 frontier

需求材料读完、原子检索进行中或完成后即可问。不要等选型完美。

```
❓ **Q1** - **使用者**：主要服务学生、教师，还是两者都有？

➡️ 按采集表已填角色；未填则师生共享但默认只读。

❓ **Q2** - **主任务**：最重要的 1–3 个「问→做→得到」里，本轮先做哪一条闭环？

➡️ 先做只读查询闭环，写入/订阅放到后续。

❓ **Q3** - **数据源**：课程知识库、结构化自有库、公开网页，还是用户当场上传？

➡️ 有老师发布资料就课程知识库；有自有案例/题库就结构化库；不要默认公开网。

❓ **Q4** - **写入**：本专家要不要改库、发布、发送或建定时任务？

➡️ 不要。先只读。

❓ **Q5** - **专家数量**：单专家还是专家团？

➡️ 单专家。专家团只在职责无法放入一个 Agent.md 红线时再拆。
```

已由用户文件写明的项不要再问。

## 后续轮 — 按依赖展开

| 已结算 | 下一轮才问 |
|---|---|
| 多个表内候选都能覆盖 | 挂哪一个、挂载顺序、是否允许两个检索类并存（默认否） |
| Q4 = 要写入 | 谁有权确认、预览字段、回滚、失败状态如何展示 |
| Q5 = 专家团 | 谁做入口/协调、共享哪份数据、交接失败怎么办、谁给最终答复 |
| 步骤 5 确认领域缺口 | 新 Skill 粒度、要不要确定性脚本、谁维护 |
| 数据源含课程点评 | 有课程证据才点评，还是通用点评（二者不可静默混用） |
| 数据源含订阅/推送 | 当前会话 Cron 回复，还是消息通道；目标不唯一时停止 |

挂载取舍必须基于选型表已有行。不要问「要不要自己写一个检索 Skill」——那不是决策，是违规。

## 停止条件

frontier 空、用户确认共享理解之后，才写 Agent.md 或平台 Skill。用户只回了部分问题：推进已结算分支，冻结未答分支。
