## 技能说明

该技能为用户提供统一的检索能力，支持知识库检索、联网搜索及二者并行检索，并按统一格式输出结果。

| 技能名称 | 功能说明 | 参考文档 |
|---------|---------|---------|
| wiki-get-kbids | 获取当前用户可用的知识库列表 | references/get_kbids.md |
| wiki-search-router | 按策略（serial / parallel / external_only）分发检索请求并合并结果 | references/router.md |
| wiki-output-format | 输出结果的统一渲染规范 | references/output_format.md |

**用户角色**：登录态用户（依赖 `userId` / `metadata` 环境变量）

---

## 意图识别

根据用户的具体需求，识别用户意图并选择对应的检索策略。各策略的详细使用流程请参考 references 目录下的文档。

| 意图类型 | 说明 | 适用策略 |
|---------|------|---------|
| 知识库优先 | 用户问题与已有知识库强相关（教学大纲、课件、产品手册、建设方案） | serial |
| 知识库+联网 | 竞品对比、对标分析或知识库覆盖不全的复杂问题 | parallel |
| 纯联网 | 行业趋势、最新动态、市场份额、融资/IPO 等与知识库无关 | external_only |

## 参数定义

### 业务参数

| 参数          | 类型 | 必填 | 默认值 | 说明 |
|-------------|------|------|--------|------|
| query       | string | ✅ | - | 用户改写后的查询语句 |
| kb_id       | string | ❌ | 自动匹配 | 知识库 ID（external_only 时可空） |
| --strategy  | string | ✅ | serial | 取值：serial / parallel / external_only |
| --text_list | 推荐 | JSON 数组字符串，3-5 条查询变体，+30% 召回 |



### 调用示例

```bash
# 1. 获取可用知识库列表
cd {this_skill_dir}/scripts && python3 get_kbids.py

# 2. 指定知识库（仅知识库检索）
cd {this_skill_dir}/scripts && python3 router.py "AI教学中心的核心功能有哪些" "1234" --strategy serial   --text_list '["智慧树AI教学平台功能模块", "AI中台能力与智能体", "数字化教学工具产品特性"]' 


# 3. 联网搜索（external_only：纯外部信息）
cd {this_skill_dir}/scripts && python3 router.py "2026年中国在线教育行业市场规模与趋势" "" --strategy external_only

# 4. 并行搜索（知识库 + 联网）
cd {this_skill_dir}/scripts && python3 router.py "2026年中国在线教育行业市场规模与趋势" "1234" --strategy parallel

# 4. 深度研究（deep_only：跨源深度分析）
cd {this_skill_dir}/scripts && python3 router.py "智慧树AI教学中心与超星学习通产品架构对比分析" "1234" --strategy deep_only --mode analyze
```

## 执行流程

```
Step 1  准备 → [强制] 获取知识库 ID（即使有历史记录，也必须重新获取以确认权限和最新状态。如未获取到，输出"缺少知识库id关键信息"并终止）
Step 2  改写 → [强制] 改写 query（保守改写，严禁增加不存在的内容）
Step 3  策略 → 选 strategy（serial / parallel / external_only）
Step 4  调用 → 执行 scripts/router.py 检索
Step 5  反思 → 评估结果质量，决定是否调整策略重试（最多 3 次）
Step 6  输出 → 按 references/output_format.md 格式渲染结果
```

> **⚠️ React 反思机制：** 必须对搜索结果进行质量评估，如果结果无法回答问题，需要自动调整策略重试，最多重试 3 次。
> **⚠️ 输出约束（重要）：**
> - **禁止输出执行过程**：不要输出 Step 1-5 的分析过程
> - **只输出最终答案**：直接输出检索结果，按照 `references/output_format.md` 格式

---

**Step 1 [PREPARE]: 获取知识库列表与选择** [强制执行]

1. 执行逻辑：无论是否存在历史对话或之前的 KB_ID 记录，必须再次调用 `scripts/get_kbids.py` 获取当前用户的可用知识库列表。
2. 选择原则：
   - 识别相关知识库 → 选出最相关的一个
   - 即使没有完全匹配，也要选择最接近的；不得伪造知识库 ID
   - 记录其他候选知识库 ID，供反思阶段切换
3. 终止条件：
   - 缺少 `userId` 或获取不到知识库列表时，立即返回 `"缺少知识库id关键信息"` 并终止

---

**Step 2 [REWRITE]: 保守改写 query + 生成 text_list [强制执行] **

1. 执行逻辑：根据知识库 description/dbPrompt 与最近会话上下文，对原始 query 进行最小化改写；核心原则：最小化干预，零幻觉扩写。
2. 规则：
   - 必须保留用户原始关键词和核心意图。
   - 消除指代（"它" → 具体主体）、补全省略
   - 仅添加主体限定，禁止凭空引入新的专业术语
   - 禁止行为： 严禁引入用户未提及的专业术语、概念或背景知识。 严禁基于“猜测”添加限定词（例如：用户问“价格”，不要擅自改为“2026年高端系列价格”除非原文有暗示）。 严禁改变问题的指向性。
   - *text_list**（3 条变体，+30% 召回）：同义替换 / 上下位概念 / 场景化

3. 终止条件：无（改写为空时使用原始 query）

---

**Step 3 [STRATEGY]: 选 strategy**

| strategy        | 场景 | 描述                                                         |
|-----------------|------|------------------------------------------------------------|
| `serial`        | KB 大概率能答（默认） | 当问题与 知识库 领域契合或属于标准文档查询时使用                                  |
| `parallel`      | 竞品对比、对标分析 | 并行检索。当问题涉及 “知识库 内容与外部信息对比” 时使用。关键词：对比、vs、竞品、差异。            |
| `external_only` | 新闻、行业趋势 | 仅限联网。当问题完全是问实时的问题，例如：当前天气，时间等等                             |
| `deep_only`     | 深度分析 / 有文件上传 | 深度内搜。当问题涉及 “知识库 文档底层细节、长文本审计、复杂逻辑推导” 时使用。不联网，仅挖掘 知识库 深度内容。 |

第一次调用不走external_only,除非明确是问实时问题。
---

**Step 4 [CALL]: 调用 router 检索**

1. 执行逻辑：调用 `scripts/router.py`，按位置参数传入 query、kb_id，并通过 `--strategy` 指定策略 以及 `--text_list`
2. 参数：
   - `query`：Step 2 改写后的查询语句
   - `kb_id`：Step 1 选定的知识库 ID（external_only 时可为空字符串）
   - `--strategy`：Step 3 选定的策略
   - `--text_list`：Step 2 改写后的text_list
3. 终止条件：
   - 网络异常或脚本超时，返回失败信息进入 Step 5 决策是否重试

---

**Step 5 [REFLECT]: React 自我反思与重试**

1. 评估标准：

   | 结果质量 | 判断标准 | 行动 |
   |---------|---------|------|
   | ✅ 完全回答 | markdown 内容完整、直接回答问题 | 进入 Step 6 |
   | ⚠️ 部分相关 | 内容相关但不完整、缺少关键信息 | 调整策略重试 |
   | ❌ 无法回答 | 结果为空、内容无关、`error=true` | 调整策略重试 |

2. 可调整维度：
   - 策略切换：serial ↔ parallel ↔ external_only ↔ deep_only
   - Query 优化：改写、扩展、简化、补充术语
   - 知识库切换：切换到候选列表中的其他相关知识库
   - **约束**：serial ≤ 2 次 · external_only ≤ 1 次 · deep_only ≤ 1 次（换 App 也算一次 db）


3. 重试规则：
   - 最多重试 3 次（含首次，共最多 3 次调用）
   - 每次重试至少调整一个维度，避免重复相同参数组合
   - 达到上限或结果满意时，整合所有检索结果
   
---


## 结果整合优先级（重要）

**在整合多次检索结果时，必须遵循以下优先级：**
1. **知识库优先**：
   - 如果知识库的答案**能够完整解决问题** → **只使用知识库答案**，不加入联网结果
   - 示例：用户问"牛顿力学是什么"，知识库有完整定义 → 仅使用知识库内容

2. **知识库补充联网**：
   - 如果知识库答案**只能回答一小部分**或**不够完整** → 知识库答案为主 + 联网结果补充
   - 示例：用户问"2026年AI趋势"，知识库只有基础概念 → 知识库定义 + 联网最新数据

3. **联网为主**：
   - 如果知识库**完全无法回答**或**结果为空** → 使用联网结果
   - 示例：用户问"最新新闻事件"，知识库无相关内容 → 仅使用联网结果

**Step 6 [OUTPUT]: 按格式输出**

1. 执行逻辑：将整合结果按 `references/output_format.md` 渲染为最终答案
2. 渲染要点：
   - 正文引用 `[1][2]` 紧跟文字
   - 参考资料分组：📄 知识库 / 🌐 互联网
   - 所有参考链接必须为可点击 Markdown 链接
3. 终止条件：无

## 执行流程强制约束
- [强制] 全流程执行：每次调用必须完整执行 Step 1 至 Step 6。严禁因为存在历史记录、缓存或之前的 KB_ID 而跳过 Step 1 (获取KB) 或 Step 2 (改写)。
- [强制] Step 1 不可省略：必须每次都调用 `scripts/get_kbids.py` 以确保证书和列表的最新性。
- [强制] Step 2 保守改写：改写过程严禁引入任何用户未提供的额外信息或假设。
- 所有 **[PREPARE]** 步骤触发终止条件时，立即返回错误信息并终止执行
- 所有 **[CALL]** 步骤必须在前置 **[STRATEGY]** 完成后执行
- 所有 **[OUTPUT]** 步骤必须在前置 **[REFLECT]** 完成后执行
- 严格按照执行流程顺序执行，不得跳过任何步骤
- 严格遵循输出约束：仅输出最终答案，禁止输出执行过程
- 错误信息必须清晰明确，便于用户理解问题原因
