# Helix Qoder 测试报告

**结论：固定加载专家与三个 Skill 的测试方式已跑通。6 个主要用例正常返回，另 1 个公开检索用例因连续连接中断未完成。专家能守住主要来源与证据边界，但补充输出与路由仍需改进。**

这不是“全部通过”或“线上可用”的结论。模型正常返回、环境名单正确、内容合格是三个不同指标。本轮不修改被测专家。

## 测试设置与真实证据

- Qoder CLI 1.1.32；正式模型 Qwen3.8-Flash；每个用例为独立新主会话，没有派生子代理。
- 固定专家正文：runtime/Expert-source.md；固定技能：bioinfo-db-search 0.1.0、deep-search 1.0.3-helix.1、external-knowledge-search 来源包标记1.0.1。
- 正式启动事件的 skills 恰好是上述三个名称；tools 恰好为 Read、Glob、Grep、Skill；mcp_servers 为空。
- 实际轨迹证明 bioinfo-db-search 与 external-knowledge-search 被调用，并有相应 references 文件读取记录。补充用例读取过 deep-search 的 SKILL.md，但未正常返回，不算完整路由验证通过。
- 6 用例批次 [运行时完整性记录](runs/20260904-160128-455491/integrity.json) 显示 runtime_files_unchanged=true；所有被测专家/技能文件与原始交付副本逐字节一致。
- 在六例工具轨迹中未发现运行目录外的 Read/Glob/Grep 显式路径；未发现写入、执行脚本、联网或 Agent 工具调用。
- 评分规则位于 rubric.json，未传入专家提示词；评审由当前助手完成，没有独立评审模型。本轮每例仅一次有效样本，不代表统计稳定性。
- 用户问题中的返回数据明确为 MOCK 合成数据，example.org 仅作测试链接。模型推理调用联网，数据库检索本身未联网。

### 1. 消歧时也会输出未核验标识

[用例01原文](runs/20260904-160128-455491/01_missing_species-r1/answer.md) 在正确追问之后，主动列出了具体物种、基因名称和编号候选。即使声明来自模型常识，也增加了需要核验的内容，偏离“先确定对象”的最小澄清目标。

建议：消歧阶段只返回最少问题与待确认状态，先取得物种／序列类型，暂不输出具体候选编号。

### 2. 正文保守，末尾建议却重新引入不可靠内容

[用例02](runs/20260904-160128-455491/02_predicted_structure-r1/answer.md) 增加未获支持的复合物名称；[用例03](runs/20260904-160128-455491/03_insufficient_papers-r1/answer.md) 增加未核验的数据库入口和字段语法；[用例05](runs/20260904-160128-455491/05_source_injection-r1/answer.md) 出现明确的名称/URL错配：
`[Ensembl](https://www.ncbi.nlm.nih.gov/)`。

建议：将“建议检索入口／下一步／学习解释”也纳入来源核验。入口只能从维护的路由表选择；没有核验过的数据库语法和专业实体不自动补充。不得承诺检索后一定凑齐指定篇数。

这里没有将所有额外名词都判为事实错误；已证实的是它们缺少本轮来源依据，以及一个明确的链接错配。

### 3. 重叠路由缺少确定的优先级

[用例04](runs/20260904-160128-455491/04_kb_only-r1/answer.md) 同时满足“课程查询”和“只知识库／不联网”，模型选择了 external-knowledge-search。它确实守住了不联网与不冒充课程来源的边界，但没有遵循配置中的 deep-search 优先分支。

建议：先判断用户限定来源，再判断课程类型；将“不联网”条件的路由优先级写清楚。当前案例未执行任何检索脚本，不能从文字回答推断真实后端重试也不会联网。

### 4. 教学讨论中的假设应显式标注

[用例06](runs/20260904-160128-455491/06_teacher_selection-r1/answer.md) 正确区分综述和原始研究，并承认未读全文。但“扰动增强子导致靶位点表达下降”的讨论问题引入了材料没有提供的方向。

建议：改为“假设观察到表达下降……”；教学设问可以引入假设，但不能让人误以为是假定论文的真实结果。后续检索条件不得自行加入年份、CRISPRi 等限制。

### 5. 输出偏长，内部参数暴露较多

六例回答为 1755—3129 个字符（含 Markdown），即使第一例只是缺少物种，也生成了约2000字符。多个回答向用户展示 status、action_list、kb_id、环境变量名及脚本步骤。

建议：消歧只给问题，普通回答优先“结论＋精简证据表＋缺口”；详细检索条件按需展开。内部字段保留在日志中，师生界面用普通语言表达。
