# 每日科技新闻

每天早 8:00 自动抓取 RSS 科技资讯，清洗、去重、过滤娱乐八卦，生成 5-10 条极简风摘要播报。

## 何时使用

- 每天早上 8:00 定时自动触发
- 用户手动呼出，查询最近 24 小时科技新闻
- 用户说"今天科技圈有什么大事""来份科技早报"等

## 使用者获得的价值

- **省时**：30 秒掌握当日科技要闻，无需逐个打开科技媒体
- **纯净**：自动过滤娱乐八卦和重复报道，只留干货
- **可靠**：每条标注来源，可追溯

## 核心流程

### ① 抓取阶段

| 动作 | 细节 |
|------|------|
| 输入 | 预设 RSS 源列表（36氪、TechCrunch、少数派等） |
| 范围 | 过去 24 小时内发布的条目 |
| 容错 | 单个源超时 10s 则跳过，不阻塞整体流程 |

### ② 清洗阶段（三步过滤）

```
拿到一条新闻 → 三步过滤：

  ├─ 去重：标题相似度 > 80% 则只保留最早一条
  ├─ 去娱乐八卦：命中关键词（明星/综艺/八卦/吃瓜/私生活…）→ 丢弃
  └─ 去过时：发布时间 > 24h → 丢弃
```

### ③ 排序阶段

按信息价值排序，优先考虑：
- 行业重大事件（融资/上市/政策/突破性技术）
- 与国内科技相关度高者优先
- 同一事件多方报道 → 优先权威来源

截取前 **5-10 条**。

### ④ 摘要阶段

每条输出格式：

```
🔥 [标题]
   [~80字摘要，一句话说清：发生了什么、为什么重要]
   📎 来源：XXX
```

### ⑤ 输出阶段

极简风，无寒暄，直接上要点：

```
📡 科技早报 | YYYY年MM月DD日

1. 标题一
   摘要一句话…

2. 标题二
   摘要一句话…

…
```

## 正例

**案例 1 — 正常工作日**
> 8:00 触发 → 36氪返回 12 条、TechCrunch 返回 8 条 → 去重后剩 15 条 → 过滤娱乐八卦剩 11 条 → 按热度排序取 Top 7 → 生成摘要 → 推送。用户 30 秒读完，掌握当日科技动态。

**案例 2 — 重大事件多源报道**
> 某 AI 公司发布重大产品，36氪、TechCrunch、少数派同时报道 → 标题相似度 >80% 被识别 → 保留最早发布的一条，其余丢弃 → 避免用户看到重复信息。

## 反例（常见误区）

- ❌ 不要强行凑满 10 条，✅ 有几条出几条，质量优先
- ❌ 摘要不要复述标题，✅ 补充"为什么重要 / 有什么影响"
- ❌ 不要过度解读或添加主观评价，✅ 客观陈述事实
- ❌ 不要静默失败，✅ 所有源不可达时明确告知用户

## 边界与例外

| 情况 | 处理方式 |
|------|----------|
| 节假日/周末新闻量不足 5 条 | 有几条出几条，不强行凑数 |
| 所有 RSS 源均不可达 | 明确告知用户，不静默失败 |
| 某条新闻跨多个分类 | 以主要话题归类，不重复出现 |
| 用户手动呼出（非定时） | 同样逻辑，拉取范围改为"最近 24h" |
