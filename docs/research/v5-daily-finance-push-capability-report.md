# Polymas V5 每日财经资讯推送与能力边界研究

> 研究日期：2026-08-17  
> 研究范围：本目录 1 份 Markdown、2 份 XLSX，以及用户已登录的 V5、专家中心、Skill 库页面。  
> 本报告只做只读研究与方案设计，未安装 Skill、未修改 V5 配置、未创建定时任务、未发送任何线上消息。

## 一、结论先行

V5 已经具备完成“财经新闻检索、筛选摘要、由专家团编排、向课程班级或班级群发送”的大部分执行能力，但当前实例还不能被证据支持为“每天固定时间、无人值守地向教师或学生推送财经新闻”。缺口不在生成内容，而在后台触发、主动投递、授权确认和学生端精准通道。

最准确的能力判断是：

| 目标 | 当前判断 | 依据摘要 |
|---|---|---|
| 教师在对话中要求生成今日财经简报 | 已支持 | `polymas-tool-skills` 可联网检索公开内容；表格把“今日热点新闻”列为支持场景 |
| 教师确认后发到指定课程班级或全部学生 | 已支持 | `polymas-teacher-activity-skills` 支持通知发布；线上专家说明与表格一致 |
| 教师确认后发到班级群 | 已支持 | `polymas-teacher-class-group-assistant` 已有线上测试通过记录，V5 广场可添加 |
| 每天固定时间自动生成简报 | 当前未打通 | 材料明确写“定时收集科研资料暂不支持，需额外配置定时任务”；当前 V5 没有已装载 MCP |
| 主动推送给教师本人的 V5 会话/频道 | 有候选能力，当前不可直接用 | 平台技能管理中有 `channel-message`，但为 0.0.1、自建、未发布；V5 广场搜索不到 |
| 使用 Cron 绑定任意 Agent 动作 | 设计上支持，当前不可视为上线 | 表格有 Cron 设计条目；平台技能管理中有未发布 `cron`；V5 广场搜索不到 |
| 向单个学生做个性化主动推送 | 未验证，不应宣称支持 | 现有可靠出口是课程通知/班级群；学生端“推送”仍标注“实现方式待定” |
| 学生直接使用当前教师 V5 小管家 | 当前实例不支持 | 当前实例位于教师 AI 教学中心；教师/学生 Skill 路由在手册中明确分离 |

因此，短期可以做“教师触发或教师审批的财经简报”；要做真正的每日自动推送，应把定时器放在 V5 对话之外，由平台 Cron/MCP 或后端调度服务触发 V5 工作流。

## 二、V5 的真实架构与能力边界

### 2.1 V5 是编排层，不是一个无限权限的后台进程

本地手册把 Skill 定义为“Markdown 文档 + Python 脚本 + 格式规范”，目录包含入口说明、参考、输出模板和业务脚本。Skill 有两种主要运行模式：

1. 编排型路由：按固定步骤把请求分发给子技能，确定性高。
2. 工具注册自主型：把脚本注册为工具，由 Agent 决定组合顺序，灵活性高，但不能违反强制约束。

手册还明确存在“专家 → 技能 → 子技能”的多层调用链。XLSX 的“生产智能体-技能映射”和“专家”Sheet 则显示：一个专家可以挂载多个 Skill，例如“教学活动专员”同时挂载作业、考试、成绩、通知、班级群、日历、资源和学情相关 Skill。

这说明 V5 的专家智能体可以理解为领域型 subagent，但专家本身不会凭空获得能力。它能做什么，取决于：

- 已挂载并启用的 Skill/MCP；
- Skill 背后的工作流/API 是否存在；
- 当前用户、学校、课程、班级和角色权限；
- Skill 是否已发布、可安装、已提测并在线；
- 运行时是否提供 `userId`、`toNid`、`traceId`、`schoolId`、`appCategory` 等上下文；
- 确认、学期校验和权限校验是否通过。

### 2.2 当前 V5 实例的可见状态

2026-08-17 的只读页面核对显示：

- “专家与专家团”页显示 16 个专家，包含教学活动专员、基础工具、检索小助手、文件理解、学情分析、创作、备课等。
- “已解锁技能”页显示 5 个已装载 Skill、0 个套件、0 个自学 Skill。
- 设置页提供 Skill、套件、自学 Skill、MCP、导入 Skill、前往技能广场等入口。
- MCP 页当前为“暂无数据”。
- “教学活动专员”已在线且启用，其说明明确包含课程通知和班级群消息。
- Skill 广场可搜索到“教学活动”1.0.7 和“班级群管家”1.0.6，并显示“添加”。
- Skill 广场搜索 `cron`、`channel-message` 和“心理科普”均为“暂无数据”。

这证明 V5 具备可扩展框架，也证明当前实例没有可见的后台调度/MCP 装载。

### 2.3 已验证可做的事情

- 联网检索公开内容，返回标题、描述、URL、平台、发布时间等。
- 理解文档、表格、PDF、图片、音视频、压缩包和代码。
- 生成 Markdown、PPT、HTML、图片、视频、图表等内容。
- 查询和管理课程、班级、作业、考试、成绩、题库、资源与教学计划。
- 查询学情、课堂表现、学习进度、教学观测和知识图谱。
- 通过教学活动 Skill 发布课程通知、查看通知、分析通知。
- 通过班级群 Skill 发消息或公告。
- 搜索/安装 Skill、Skill Suite、MCP 等能力。
- 使用专家团把复杂任务拆给不同领域专家处理。

### 2.4 不能直接推断或当前明确欠缺的事情

- 不能把一个 Prompt 当成后台定时器；对话结束后不会因为写了“每天 8 点”就自动持续运行。
- 当前没有证据证明 Cron 已在本 V5 实例发布、安装并可执行。
- 当前没有证据证明 V5 能在无会话状态下自动恢复完整身份、学校、课程和班级上下文。
- 当前没有证据证明可以向任意单个学生进行个性化主动消息推送。
- 学生端“查询待办/课程通知”和“主动向学生发送消息”是两件事，前者已有资产，后者仍有缺口。
- “资源支持定时自动发布”只适用于学习资源，不能扩大解释成任意 Agent 工作流都能定时执行。
- `earnings-analysis` 是业绩/权益研究报告 Skill，不是实时财经新闻源，也不等于新闻分发通道。
- 表格中 Cron、Hook、会话和记忆等条目缺少提测/测试状态，属于设计资产，不能当成当前线上事实。

## 三、为什么现在不能直接配置成全自动推送

证据之间存在一组很有价值的“设计—上线状态”差异：

1. `技能一览表.xlsx` 的“Agent与Skill列表”写有 Cron：可创建周期任务或一次性任务、绑定任意 Agent 动作、失败告警。
2. 同一工作簿的“推广问题修复”又明确写“定时收集科研资料暂不支持”“需额外配置定时任务”。
3. 平台技能管理页面能搜到 `cron` 和 `channel-message`，二者均为 0.0.1、自建、未发布。
4. V5 技能广场搜索二者都没有结果，当前 MCP 页也为空。

所以 Cron 是明确的产品方向或候选实现，而不是当前 V5 已具备的生产能力。

另一个阻塞是确认机制。材料要求班级群的对外发言必须经教师确认，手册也规定写入/发布存在确认和当前学期校验。无人值守自动推送若没有“创建订阅时一次授权”的产品级规则，会在每次发布前卡在确认步骤。这不能靠 Prompt 绕过，应由平台正式定义授权、撤销、审计和范围限制。

## 四、推荐的目标架构

### 4.1 专家与 Skill 组合

建议新建一个“财经资讯推送专员”，按高确定性的工作流模式挂载：

1. `polymas-tool-skills`：联网检索公开财经信息。
2. 新建 `financial-news-digest`：限定来源、时间窗、去重、事实核查、摘要和输出格式。
3. `polymas-teacher-activity-skills`：发布课程通知。
4. `polymas-teacher-class-group-assistant`：发送班级群消息/公告。
5. 条件挂载 `cron`：发布并验证后才启用，用于固定时间触发。
6. 条件挂载 `channel-message`：仅用于教师个人会话/频道；不能默认当作学生端通道。

推荐执行链：

```text
后台调度器
  → 恢复订阅与身份上下文
  → 检索过去 24 小时可信财经来源
  → 去重、交叉核验、筛选
  → 生成带来源与时间戳的简报
  → 审批/预授权策略
  → 课程通知、班级群或教师频道
  → 记录结果、失败重试与告警
```

### 4.2 `financial-news-digest` 的最小合同

输入应至少包含：

- 主题：宏观、资本市场、行业、公司、政策等；
- 时间范围：默认上次成功时间到本次执行时间；
- 来源白名单；
- 接收对象：教师本人、课程全部学生、指定班级、班级群；
- 时区与执行时间；
- 每次条数、语言、篇幅；
- 审批模式：逐次审批或已授权的固定模板；
- 风险约束：只做资讯与教学解读，不生成个性化买卖建议。

每条输出应强制包含：

- 标题；
- 2–3 句事实摘要；
- 教学相关性或“为什么值得关注”；
- 来源名称、原文 URL、发布时间；
- “事实 / 分析”区分；
- 数据不足或来源冲突说明。

### 4.3 定时器应放在哪里

优先级建议如下：

1. **生产推荐：后端调度服务/队列。** 调度器保持确定性，V5 只负责内容处理和专家路由。通过正式工作流/API 调用，不使用浏览器自动化。实现幂等、重试、告警、审计和停用开关。
2. **平台原生试点：发布并安装 `cron`。** 先验证 `copaw cron` 的真实运行环境、`--agent-id`、时区、失败告警和上下文恢复，再用于小范围教师频道试点。
3. **人工 MVP：教师每天手动触发。** V5 完成检索、摘要和通知草稿，教师确认后发送。它不满足“固定时间自动”，但可以最先验证内容质量和投递链路。

不建议用浏览器脚本定时登录、点按钮和发送消息。页面变动、登录态、二次确认和网络异常会导致不可审计的失败。

## 五、教师端和学生端应分开设计

### 教师本人

最适合先做试点。目标通道可以是 V5 会话/频道、日历提醒或教师通知中心。其中 `channel-message` 是候选出口，但需要先发布、安装并验证会话映射。

### 课程班级或全部学生

当前最可靠的出口是“课程通知”，其次是“班级群消息/公告”。这两类能力有线上页面和表格证据。仍需明确：课程、学期、目标班级、标题、内容、附件和教师授权。

### 单个学生的个性化推送

当前不能直接承诺。需要平台补充：

- 学生用户/会话/设备的可投递标识；
- 学生端消息发送 API 或可安装 Skill；
- 订阅、退订、静默时段、频率和隐私同意；
- 失败与退信状态；
- 教师授权范围与内容审计。

在这些能力上线前，可以把个性化结果生成给教师，再由教师选择发布；不要把课程群发伪装成个人精准推送。

## 六、分阶段落地方案

### 阶段 0：验证内容与人工发布

- 创建“财经资讯推送专员”和 `financial-news-digest`。
- 检索近 24 小时信息，生成 3–5 条带来源的简报。
- 教师预览并确认。
- 通过课程通知或班级群发送。
- 验证学生是否真实可见、链接是否可达、已读数据是否返回。

### 阶段 1：教师端定时试点

- 由平台发布 `cron` 与 `channel-message`，或使用后端调度服务。
- 只推送给少量教师账号。
- 验证时区、重复执行、失败重试、告警、暂停/恢复和上下文恢复。
- 初期保留“生成后待教师确认”，稳定后再评估预授权自动发送。

### 阶段 2：课程级自动推送

- 使用课程通知/班级群作为学生可见通道。
- 订阅配置绑定课程、班级、当前学期和教师负责人。
- 使用 `subscription_id + scheduled_date + audience` 作为幂等键，避免重复发送。
- 配置去重窗口、节假日/交易日规则、内容归档和撤销/停用开关。

### 阶段 3：学生个性化推送

- 新增正式的学生端主动消息能力。
- 以学生订阅和授权为前提进行画像匹配。
- 对财经内容增加适龄、合规和非投资建议约束。
- 逐个验证投递结果，不以“任务执行成功”代替“学生已收到”。

## 七、上线前必须通过的门禁

- `cron` 已发布、可安装、已提测，并在目标 V5 中启用。
- MCP/运行时能够在无对话时恢复完整用户与课程上下文。
- 通知发布支持当前学期校验，目标班级精确匹配。
- 自动发布的授权规则由产品明确，不通过 Prompt 规避确认。
- 财经来源白名单、发布时间、原文链接和去重策略可审计。
- 推送任务有幂等键、重试上限、失败告警和人工停用开关。
- 教师端、课程群发、单学生通道分别做真实投递测试。
- 报告中区分“生成成功、发送成功、接收成功、已读成功”。
