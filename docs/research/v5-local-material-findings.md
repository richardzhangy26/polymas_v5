# Polymas V5 本地材料研究：专家、Skill、定时推送与能力边界

> 日期：2026-08-17  
> 范围：只读分析当前目录内 Markdown/XLSX；未访问网页，未验证预发/生产，未修改原始材料。  
> 标签：**[明确支持]** 材料直接写明；**[合理推断]** 可由组件组合但无完整验收；**[材料未说明]** 本地材料不能确认。

## 一、核心结论

1. **V5 架构上可以设计“定时检索财经新闻 → 去重/摘要 → 向老师或学生投递”，但不能根据本地材料声称这条链路已经生产可用。**
2. 材料分别列出 Cron、Web Search/DeepRag、教师课程通知、班级群消息、会话和记忆；但 Cron 没有提测/测试状态，同一工作簿另写“定时收集科研资料暂不支持，需额外配置定时任务”。
3. 学生端“推送”已列入需求，却明确标注“实现方式待定”。教师侧通知与班群消息证据更成熟，适合先做受控 PoC。
4. 本地没有“财经新闻”专家、Skill、RSS/API 或专业行情源。只有“今日热点新闻”通用检索样例，以及技能广场截图中的 earnings-analysis 季度业绩分析 Skill；后者不是新闻源或定时投递能力。
5. V5 的真实边界是“Agent 编排 + 已挂载 Skill + 有权调用的平台 API/工作流”。没有 Skill/API 的业务在映射表中明确写为“不触发”。
6. 材料明确采用“专家 → 技能 → 子技能”调用链，但没有定义“专家团”的并行、递归委派、冲突仲裁、最大层级或成本限制。把专家类比为 subagent 合理，但不能据此扩大承诺。

## 三、V5 结构与能力模型

### 3.1 Skill 不是单一提示词

**[明确支持]** 手册第 5–7 行：Skill = Markdown 文档 + Python 脚本 + 格式规范；第 31–44 行：目录包含 SKILL.md、references、output_format、scripts/base 和业务脚本。

- SKILL.md：意图、流程、触发条件、强制约束。
- references：子技能流程、参数、返回结构。
- Python：真实接口调用和数据处理。
- output_format：用户可见输出契约。
- 最终动作边界：Skill 对接的 API、工作流和当前权限。

### 3.2 两种编排

| 模式 | 机制 | 边界 | 证据 |
|---|---|---|---|
| Workflow Routing | 固定 Step 串行分发子技能 | 确定性高、灵活性低 | 手册第 49–68、85–95 行 |
| Tool-Use Agent | 注册脚本为工具，Agent 自主组合 | 灵活，但不得突破强制约束 | 手册第 72–95 行 |

**[合理推断]** 财经推送应以 Workflow 固定时间、来源、去重、格式、投递与审计，只在排序/摘要环节使用 Agent 判断。

### 3.3 专家 → Skill → 子技能

**[明确支持]** 手册第 1108–1114 行直接写出该多层架构。技能  - 专家整理.xlsx 的 专家!A2:G2 定义类型、专家名称、描述、附属技能、触发场景等字段。

典型一对多：

- 基础工具：专家!B4:D6；
- 教学活动专员：专家!B7:D19；
- 学情分析专员：专家!B20:D24；
- 课程管理专员：专家!B27:D35；
- 智能体课程专员：专家!B36:D37；
- 资源管理专员：专家!B38:D43。

**[材料未说明]** 专家团并行、递归、仲裁、队列、超时、成本均无契约。

### 3.4 执行与身份边界

**[明确支持]**

- Skill HTTP 统一走 workflow_client.py，网关统一 POST（手册第 123–188 行）。
- 运行时注入 metadata、userId、toNid、traceId、schoolId、appCategory（第 239–315 行）。
- 教师/学生课程搜索路由分离，不可混用（第 576–586、815–826 行）。
- 业务-专家!B47:G58 中，无附属 Skill/无匹配 Skill 的业务均“不触发”。

## 五、建议实现

> 以下为 **[合理推断]**，不是现网确认。

### 5.1 新增“财经资讯专员”

| Skill | 职责 | 复用/新增 |
|---|---|---|
| finance-push-preference | 创建/修改/暂停/取消订阅；保存受众、主题、时间、时区、频率、通道 | 复用记忆概念；新增订阅 CRUD |
| finance-news-retrieve | 按时间窗、主题、白名单检索；保留链接、来源、发布时间 | 复用 Web Search/DeepRag；专业数据需新接口 |
| finance-news-digest | 去重、聚类、排序、摘要、事实/观点区分、风险提示 | 复用 Agent；新增固定输出契约 |
| finance-news-deliver | 投递定稿内容 | 复用教师通知/班群；个人推送需新 API |
| finance-push-audit | 记录调度、来源、版本、受众、送达、失败和重放 | 复用 Cron 告警概念；新增审计/回执 |

触发范围只包括财经早报/晚报、主题订阅、暂停/恢复/取消、立即生成一期；不执行交易或无关教学写操作。

### 5.2 固定流程

1. 用户创建订阅并明确授权。
2. 保存时区、受众、来源和下次执行时间。
3. Cron 触发检索。
4. 白名单/时间窗过滤，去重和事件聚类。
5. 生成带原链接、来源、发布时间、免责声明的摘要。
6. 质量门禁：无来源、过时、重复、疑似幻觉则不发。
7. 投递，保存内容版本和回执。
8. 失败告警，按 subscriptionId + scheduleDate + edition 幂等重试。

### 5.3 最小 PoC

先做：**教师建立财经早报计划 → 每天生成草稿 → 教师确认 → 通过课程通知发给测试班级。**

这条路径复用证据最成熟的通知出口，符合“对外发言需教师确认”，也不依赖学生个人主动推送。

### 5.4 自动发布与确认冲突

手册第 1093–1114 行要求不可逆发布保留确认；上游确认只有“可见可核对、逐项一致、轻量可逆”时可向下游传递。第 1187–1197 行把发布通知归为当前学期根实体创建；SKILL开发方向划分!K120 要求对外群消息必须教师确认。

因此当前规范没有定义“一次确认订阅后，Cron 永久无人值守发布”的持续授权。必须明确选择：

1. **每次审核后发**：Cron 只生成草稿，符合现行规则，但不是全自动。
2. **持续授权自动发**：创建订阅时确认受众、来源、模板、频率、生效期、取消和风险声明；需新增产品、安全、审计契约，不能只改 Skill 文案。

## 六、V5 能力边界

### 能做

- 自然语言路由到专家、Skill、子技能；
- 选择固定 Workflow 或自主 Tool-Use；
- 通过已挂载 Skill 查询/受控写入课程、班级、作业、考试、成绩、通知、群聊、资源、题库、智能体课堂等；
- 使用联网搜索、文件、Office/PDF、AIGC 工具；
- 一个专家挂多个 Skill；
- 使用用户、目标、学校、应用类别和链路上下文；
- 设计层面存在 Cron、Hook、会话、记忆等自动化组件。

### 不能宣称或明确受限

- 没有 Skill/API 不能执行平台动作；
- 不能绕过角色、权限、归属、学期和确认（手册第 1125–1175、1221–1225 行）；
- 不能把专家团解释为无限自治多 Agent；
- 不能声称已经端到端定时推送；
- 不能把 Web Search 当专业实时金融数据；
- 不能把能力清单自动当生产上线清单；
- Skill 安装状态有冲突：V5技能!C8:F8 描述支持，但 技能一览!A8:J8 验证列写“不支持”；
- 智能体教学状态也须逐项报告，SKILL开发方向划分中同时存在测试通过和不通过项。

## 七、上线前必须现场核验

1. Cron 是否上线；配置 UI/API、route、时区、历史、重试、幂等、告警是什么？
2. 用户退出后是否继续？如何恢复 userId、toNid、schoolId、appCategory 和 Token？
3. 教师个人、学生个人、课程班级、班级群、App Push 分别是什么 API，有无送达/已读回执？
4. 一次订阅确认能否替代每次发布确认？有效期、取消、模板变更和审计如何定义？
5. 财经源使用 Web Search、知识库还是采购 API？授权、转载长度、延迟、更正机制是什么？
6. 无新闻、超时、单源失败、通知失败、部分送达、重复触发时如何降级？
7. 学生端“实现方式待定”对应哪个版本、API 和责任人？

## 八、建议验收门禁

### 安全范围 PoC

- 只发测试课程/班级，固定 Asia/Shanghai，每日一次；
- 白名单来源，每条保留原链接、来源、发布时间；
- Cron 先生成草稿，教师确认后发布；
- 模拟超时、失败、重复触发，确保同订阅同一期只发一次；
- 可从摘要回溯检索结果、来源、生成版本、受众和送达结果。

### 真实环境

- 分别用教师、学生、离班/无权用户验证权限隔离；
- 逐个验证所有批准通道；
- 验证退出、Token 过期、课程归档、时区切换后的 Cron；
- 验证修改、暂停、取消后不误发；
- 通过财经来源、版权、数据合规和风险声明审查。
